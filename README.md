# hxwl-12 心理咨询会谈复核台

咨询师会谈登记、风险分级、督导意见逐条复核、版本化归档与转组交接的单机工作台。

## 技术栈

React 19 + Vite + TypeScript + 原生 CSS，数据持久化在本机 **IndexedDB**（无后端）。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5112。`npm run build` 产出静态文件；`npm test` 运行数据层不变量冒烟测试。

## 业务规则

### 登记
- 咨询师登记：会谈日期、**登记摘要**、情绪状态、干预方法、**下一步计划**、**风险等级**、教学个案标记、**归档期限**。
- **高风险或教学个案**提交后自动进入督导复核队列。
- 中低风险个案可直接归档（督导若手动补意见，同样必须逐条处理完）。

### 意见逐条复核（没处理完不能归档）
- 督导对个案逐条登记意见，每条意见三态：`未处理 → 已修改·待督导确认 → 已确认处理`。
- 咨询师必须先在登记中修改并提交修订（自动另存新版本），才能对一条意见提交「修改说明」。
- 督导逐条确认；任一条处于未处理/待确认状态时，**归档按钮禁用**并显示剩余条数。
- 高风险/教学个案还需督导点「复核通过」；内容再次修订后，复核通过失效，需重新通过。
- 督导可「退回重做」把意见打回未处理。

### 改过的内容另存新版本
- 每次提交修订生成一个「修订另存」版本（修订序号、登记版本号、修改人、修订说明、完整快照）。
- 归档时再生成一个「归档版本」快照；两类版本在版本面板分区标记，可展开查看当时的全部字段。
- 当前登记带版本号 v1/v2…，意见记录其针对的版本号。

### 转组交接
- 负责咨询师或管理员办理转组：个案归属改为接手人，原咨询师留痕。
- **未结意见随案交接**：接手人能看到原始意见内容、提出人、提出时间和当时版本。
- 归档期限不变，列表与详情横幅持续显示剩余/逾期天数。
- 未提交的本机草稿不随人交接（草稿是本机的，正式数据是共享的）。

### 四个库分开维护
IndexedDB 中四个对象库各自独立，互不覆盖：

| 对象库 | 内容 |
| --- | --- |
| `cases` | 个案与当前会谈登记 |
| `reviews` | 督导复核记录与逐条意见（含处理留痕） |
| `archiveVersions` | 修订另存版本与归档快照 |
| `localDrafts` | 仅本机保存的未提交草稿 |

重开/刷新页面后自动从本机读回，草稿、未结意见、复核进度都可以接着处理。右上角「恢复示例数据」可重置。

## 演示身份

可在右上角切换：林/赵/沈三位顾问、秦/何两位督导、机构管理员（不同身份看到的操作按钮不同）。

种子数据覆盖：高风险待复核（C-203）、教学个案（C-118，含一条已确认/一条未结意见）、已转组个案（C-119）、已归档个案（C-042）。

## 目录

- `src/types.ts` — 领域模型
- `src/db.ts` — IndexedDB 四个对象库封装
- `src/seed.ts` — 示例数据、人员目录、剩余天数计算
- `src/components/CaseForm.tsx` — 登记表单（草稿自动保存、必填校验）
- `src/components/CaseList.tsx` — 个案队列（在办/待复核/我负责/已归档、搜索、剩余时间）
- `src/components/ReviewPanel.tsx` — 督导意见逐条复核
- `src/components/VersionsPanel.tsx` — 修订与归档版本
- `src/components/CaseDetail.tsx` — 个案工作台（登记、归档门禁、转组）
- `scripts/smoke.ts` — 数据层不变量冒烟测试
